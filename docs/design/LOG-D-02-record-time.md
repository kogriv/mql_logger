# LOG-D-02: Время записи

**Статус:** реализован (07.10.2026)  ·  **Задачи:** LOG-BL-08, LOG-BL-07

## Задача

По журналу восстановить порядок событий и промежутки между ними; не показывать того, чего не знаем.

## Сейчас (до изменения)

Одно поле `timestamp` из `TimeCurrent()` (время последнего тика, секунды) и выдуманные миллисекунды в подробном
формате; автосброс буферов по `TimeCurrent()`.

## Решение

В `SLogRecord` — четыре значения, заполняются одной функцией `LogStampRecord`:

| Поле | Источник | Поле шаблона | Столбец базы |
|---|---|---|---|
| `timestamp` | `TimeCurrent()` — время сервера, в тестере — модели | `%timestamp%` | `timestamp`, `ticktime` |
| `time_local` | `TimeLocal()` — часы компьютера (в тестере равны времени модели) | `%localtime%` | `time_local` |
| `elapsed_us` | `GetMicrosecondCount()` — микросекунды от запуска программы | `%elapsed%` (секунды, 6 знаков) | `elapsed_us` |
| `sequence` | счётчик записей программы, с 1 | `%seq%` | `seq` |

- Шаблоны по умолчанию по-прежнему показывают `%timestamp%`: журнал советника сверяют с журналом терминала и
  сделками, а там время сервера. Кому нужны промежутки — добавляет в шаблон `%elapsed%`.
- Настоящих миллисекунд часов компьютера в MQL5 без DLL нет, поэтому их в записи нет; `.NNN` из
  `GetTickCount()` убраны.
- Автосброс (`CLogger`, `CFileHandler`) — по `GetTickCount64()`, от тиков не зависит.
- Запись, созданная конструктором без параметров, не отмечена временем (нули): отметку ставят
  `CreateLogRecord()`, конструктор с параметрами и сам логгер.

## Что рассмотрено и отвергнуто

- Показывать по умолчанию часы компьютера — меняет привычный вид журнала и расходится с журналом терминала.
- Убрать `thread_id` — поле оставлено (всегда 0), чтобы не ломать чужой код и таблицы.

## Совместимость

Новые поля структуры — в конце; код, который заполнял запись сам, собирается. Таблица базы — см. LOG-D-01.

`sqlite: time columns are stored, an older table is upgraded`.
