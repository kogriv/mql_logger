# LOG-BL-08: Время записи — модель, компьютер, микросекунды

**Статус:** сделано (07.10.2026)  ·  **Приоритет:** P2
**Создано:** 2026-10-07  ·  **Источник:** LOG-GAP-06, F-18, F-19, F-12  ·  **Зависит от:** LOG-BL-01; вместе с LOG-BL-04
**Затрагивает:** `Core/LogRecord.mqh`, форматтеры, `Handlers/SqliteHandler.mqh` (таблица), автосброс в
`Core/Logger.mqh` и `Handlers/FileHandler.mqh`; потребители — новые поля, старый код собирается

## Зачем

Секундная точность по времени последнего тика; автосброс, который не срабатывает без тиков.

## Что сделать

Сначала проект `design/LOG-D-…-record-time.md`:
- поля записи: время торгового сервера или модели (`TimeCurrent`), время компьютера (`TimeLocal` или `TimeGMT` —
  выбрать), микросекунды от запуска программы (`GetMicrosecondCount`), порядковый номер;
- что показывать по умолчанию на графике и в тестере (`MQLInfoInteger(MQL_TESTER)`);
- цена `TimeLocal` + `GetMicrosecondCount` на запись — замерить;
- таблица базы: один столбец времени модели, один — компьютера, оба целые 64 бита; убрать `(int)`;
- автосброс — по `GetTickCount64()`.

Затем реализация; поле `thread_id` (всегда 0) — убрать или заменить на идентификатор графика.

## Готово, когда

В журнале графика — настоящие миллисекунды; в тестере — время модели и микросекунды от начала прохода; буфер
файла сбрасывается через заданный интервал при отсутствии тиков.

## Сделано (07.10.2026)

Проект — [`design/LOG-D-02`](../design/LOG-D-02-record-time.md).

- `SLogRecord`: добавлены `time_local`, `elapsed_us`, `sequence`; отметку ставит `LogStampRecord()`.
- Поля шаблона `%localtime%`, `%elapsed%`, `%seq%`; столбцы базы `time_local`, `elapsed_us`, `seq`;
  `timestamp` пишется 64-битным.
- Автосброс в `CLogger` и `CFileHandler` — по `GetTickCount64()`.
- Шаблоны по умолчанию показывают время сервера, как раньше (обоснование — в проекте); настоящих миллисекунд
  часов компьютера в MQL5 нет, вместо них — микросекунды от запуска программы.
- `thread_id` оставлен (всегда 0).
