# LOG-BL-09: Фабрика — владение, повторное создание, имена, `LOGIF`

**Статус:** новая  ·  **Приоритет:** P2
**Создано:** 2026-10-07  ·  **Источник:** LOG-GAP-07, F-25 … F-31  ·  **Зависит от:** LOG-BL-01
**Затрагивает:** `Factory/LoggerFactory.mqh`, `Core/Macros.mqh`, `Core/Logger.mqh`; потребители — недопустимое имя
перестаёт молча превращаться в `default`

## Зачем

Ошибки использования скрываются; срок жизни обработчиков не определён.

## Что сделать

Короткий проект `design/LOG-D-…-ownership.md` (кто владеет обработчиком, форматтером, фильтром; что делает
`RemoveLogger`), затем:
1. `RemoveLogger` освобождает то, чем владел логгер; общий обработчик не закрывается, пока им пользуется другой.
2. Повторное создание с тем же именем: правило из проекта (вернуть существующий молча либо пересоздать) — без
   строки в журнал при штатном повторном `OnInit`.
3. Имена: разрешить точку; недопустимое имя — `NULL` и одна строка в журнал.
4. `CreateProfileLogger`: общая часть трёх веток — в одну функцию; ветка `default` не удаляет объект из-под реестра;
   сообщение «initialized with … profile» — уровнем `INFO`.
5. `LOGIF` — починить (или удалить вместе с упоминанием в README); `LOGEXECUTION_TIME` — на `GetMicrosecondCount`.
6. Убрать `#property strict`, приведения `(ENUM_LOG_LEVEL)N`, закомментированные блоки.

## Готово, когда

Тесты на имена, повторное создание и удаление проходят; сборка всех макросов — в тесте.
