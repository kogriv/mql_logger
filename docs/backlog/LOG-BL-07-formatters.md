# LOG-BL-07: Форматтеры — шаблон в один проход, текст не трогать

**Статус:** новая  ·  **Приоритет:** P2
**Создано:** 2026-10-07  ·  **Источник:** LOG-GAP-09, LOG-GAP-06, F-18, F-20 … F-24  ·  **Зависит от:** LOG-BL-01
**Затрагивает:** `Formatters/*`, `Handlers/ConsoleHandler.mqh`, `Handlers/FileHandler.mqh`; потребители — меняется
вид строк в журнале и файле

## Зачем

Форматтер меняет текст сообщения (пробелы, подстановки внутри текста), теряет код ошибки и печатает выдуманные
миллисекунды.

## Что сделать

1. Общий разбор шаблона при `SetPattern` в массив кусков «текст / поле»; `Format` — один проход, значения полей
   не просматриваются повторно.
2. Пробелы: убирать только те, что остались вокруг пустого поля; текст сообщения — как есть.
3. `CSimpleFormatter`: `%logger%` подставляется, если есть в шаблоне; флаги `SetShow…` убрать или оставить
   псевдонимами.
4. Миллисекунды из `GetTickCount()` убрать сразу; настоящее время — LOG-BL-08.
5. Один формат по умолчанию для журнала и файла, включает код ошибки (с текстом ошибки, если известен) и место
   вызова, когда они заданы.
6. Цвета ANSI удалить.
7. Таблица полей шаблона — в README.

## Готово, когда

Тест: сообщение `a  b   c %file% %level%` выходит без изменений при любом шаблоне; `Error("x", 4756)` в журнале
содержит 4756; форматирование одной записи дважды даёт одну и ту же строку.
