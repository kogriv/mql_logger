# LOG-BL-04: SQLite — подготовленный запрос, транзакции, тишина в журнале

**Статус:** новая  ·  **Приоритет:** P2
**Создано:** 2026-10-07  ·  **Источник:** LOG-GAP-04, F-10 … F-13  ·  **Зависит от:** LOG-BL-03; вместе с LOG-BL-08
**Затрагивает:** `Handlers/SqliteHandler.mqh`, профили фабрики; потребители — записи коммитятся пакетами

## Зачем

1,9 мс на запись в режиме по умолчанию: профиль `DEBUG` на 10 000 записей прохода добавляет 19 секунд.

## Что сделать

Сначала проект `design/LOG-D-…-sqlite-write-path.md`:
- подготовленный запрос на обработчик (`DatabasePrepare`, привязка значений, `DatabaseRead`, `DatabaseReset`);
- транзакция всегда; коммит по числу записей, по времени, в `Flush`, при закрытии и сразу после записи уровня
  `ERROR` и выше (чтобы причина падения не осталась в незакоммиченном пакете);
- что теряется при аварийном завершении и как это объяснить пользователю;
- индексы: какие нужны при записи, какие создавать при чтении;
- схема таблицы вместе с LOG-BL-08 (время) и версия схемы (`PRAGMA user_version`), перенос старых баз;
- служебные строки в журнал терминала — убрать или через отдельный внутренний уровень, выключенный по умолчанию;
- два экземпляра программы на одну базу (F-13): проверить, что происходит, и решить — общий файл или имя с
  идентификатором графика.

Затем реализация и замер.

## Готово, когда

Запись в профиле `DEBUG` — не дороже 100 мкс (сейчас 1 900); в журнале терминала от обработчика — только ошибки;
старая база открывается новой версией.
