# LOG-BL-01: Тесты с проверками, запуск `mql-test unit`

**Статус:** новая  ·  **Приоритет:** P1
**Создано:** 2026-10-07  ·  **Источник:** LOG-GAP-01, F-34  ·  **Зависит от:** —
**Затрагивает:** `Tests/`, `LoggerTest.mq5` в корне; в `mql` — `Scripts/Logger`, `Scripts/UnitTests`

## Зачем

18 находок разбора подтверждены одноразовой пробой; ни одна не ловится имеющимися «тестами». Исправлять без
тестов — значит проверять глазами по журналу.

## Что сделать

1. Каркас проверок: либо `Include/UnitTest.mqh` из `mql`, либо свой файл в `Tests/` с тем же итогом
   «N of M passed» (решить; см. варианты в LOG-GAP-01).
2. Обработчик-счётчик для тестов (считает записи, помнит последнюю) — проверять ядро без файлов.
3. Наборы:
   - ядро: уровни, включение/выключение, несколько обработчиков, вложенная запись (сейчас теряется — F-14);
   - файл: дозапись между сеансами (F-01), ротация без потерь (F-02), имя архива (F-03);
   - SQLite: число записей (F-07), пакетный режим без ошибок (F-08, F-09), содержимое строки;
   - форматтеры: текст сообщения не меняется (F-20, F-21), `%logger%` (F-22), код ошибки (F-23);
   - фабрика: имена (F-25), повторное создание (F-26), удаление (F-27), профили;
   - макросы: все раскрываются и собираются, включая `LOGIF` (F-30).
4. Тесты убирают свои файлы из `MQL5\Files`.
5. Тест на известную ошибку пишется сразу и помечается ожидаемо падающим до исправления (список в выводе).
6. Старые демонстрации: оставить одну как пример использования (`Examples/`), дубль в корне и `.ex5` удалить.
7. В `mql`: `Scripts/UnitTests/Logger` → запуск `mql-test unit`; `Scripts/Logger` (копии демонстраций) убрать.

## Готово, когда

`mql-test unit Scripts/UnitTests/Logger` проходит из Linux; каждая находка тяжести A и B из разбора покрыта
случаем; после тестов в `MQL5\Files` нет их файлов.
