# LOG-BL-05: Дешёвый выключенный уровень

**Статус:** сделано (07.10.2026)  ·  **Приоритет:** P1
**Создано:** 2026-10-07  ·  **Источник:** LOG-GAP-02, F-15, F-16, F-17, F-32  ·  **Зависит от:** LOG-BL-01
**Затрагивает:** `Core/Macros.mqh`, `Core/Logger.mqh`, `Factory/LoggerFactory.mqh`; старые вызовы продолжают работать

## Зачем

Выключенный вызов стоит 2,4–5,4 мкс вместо 0,01; профиль «для оптимизации» медленнее обычного логгера.

## Что сделать

1. Макросы для указателя на логгер, аргумент вычисляется только при включённом уровне:
   `LOGTRACE_TO(p, msg)`, `LOGDEBUG_TO`, `LOGINFO_TO`, `LOGWARN_TO`, `LOGERROR_TO(p, msg)` (код — `GetLastError()`,
   прочитанный **до** остального), `LOGERROR_CODE_TO(p, msg, code)`, `LOGFATAL_TO`. Раскрытие:
   `if(p != NULL && p.IsEnabled(LOG_X)) p.Log(LOG_X, msg, code, __FILE__, __LINE__, __FUNCTION__)`.
   Имена — обсудить; `LOG_INFO(...)` занять нельзя (значение перечисления).
2. Существующие `LOGINFO(...)` и `LOGINFO_N(...)` — та же проверка уровня до вычисления сообщения; внутренняя
   переменная с именем, которое не встретится у вызывающего (F-31).
3. Фабрика хранит указатель на `default` — макросы без имени не ищут по реестру.
4. Профили: уровень логгера = наименьший из уровней его обработчиков (`PERFORMANCE` → `WARN`).
   `CLogger::AddHandler` уровень сам не меняет — это делает профиль.
5. `IsEnabled` логгера — без повторной проверки `m_enabled`.
6. Замер до и после тем же способом, что в разборе; цифры — в историю изменений.

## Готово, когда

Выключенный вызов через новый макрос — не дороже 0,05 мкс; профиль `PERFORMANCE` с вызовом `TRACE` — столько же;
`LOGINFO("x")` при 25 логгерах — без поиска по имени.

## Сделано (07.10.2026)

- `Core/Macros.mqh` переписан: общий макрос `LOGGER_WRITE` сначала проверяет `IsEnabled(level)` и только потом
  вычисляет сообщение; внутренние переменные — с именами `_lg_…_` (F-31).
- Новые макросы для указателя: `LOGTRACE_TO`, `LOGDEBUG_TO`, `LOGINFO_TO`, `LOGWARN_TO`, `LOGERROR_TO`,
  `LOGFATAL_TO` (код — `GetLastError()`, прочитанный первым), `LOGERROR_CODE_TO`, `LOGFATAL_CODE_TO`;
  указатель `NULL` допустим.
- `LOGINFO(...)` и другие без имени берут `CLoggerFactory::Default()` — указатель хранится в фабрике, поиска нет.
  `…_N("имя", …)` по-прежнему ищут по имени на каждый вызов (так и записано в комментарии).
- Профили ставят уровень логгера по наименьшему уровню обработчиков: `PERFORMANCE` — `WARN`, `PRODUCTION` —
  `INFO`, `DEBUG` — `TRACE`. Сообщение «initialized with … profile» — уровнем `INFO` (в журнал терминала не идёт).
- Заодно из LOG-BL-09: `LOGIF` собирается и работает (F-30); `LOGEXECUTION_TIME` — на `GetMicrosecondCount`.

**Замер после** (выключенный `TRACE`, сообщение через `StringFormat`, 2 млн вызовов):

| Вызов | Было | Стало |
|---|---|---|
| `logger.Log(LOG_TRACE, StringFormat(...), …)` напрямую | 2,4 мкс | 2,2 мкс (строку строит вызывающий — LOG-BL-12) |
| `LOGTRACE_TO(ptr, StringFormat(...))` | — | **0,011 мкс** |
| `LOGTRACE(StringFormat(...))`, 26 логгеров в фабрике | 5,4 мкс | **0,015 мкс** |
| `LOGTRACE_N("имя", …)` | 5,4 мкс | 5,5 мкс (поиск по имени) |

- Тесты: сообщение не вычисляется при выключенном уровне (пометка F-15 снята), макросы для указателя, `LOGIF`,
  уровни профилей (пометка F-16 снята), `Default()`.
