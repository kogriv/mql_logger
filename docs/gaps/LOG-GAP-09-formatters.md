# LOG-GAP-09: Форматтеры искажают сообщение

**Статус:** закрыт (07.10.2026)  ·  **Дата:** 2026-10-07  ·  **Находки:** F-20 … F-24  ·  **Задачи:** LOG-BL-07

## Что нужно

Текст сообщения попадает в журнал таким, каким его передали; всё, что передано вместе с ним (код ошибки, место
вызова), не теряется молча.

## Что есть (проба 07.10)

Запись с текстом `a  b   c %file% %level%`, логгер `mylog`, файл `F.mq5`:

| Форматтер | Результат |
|---|---|
| `CSimpleFormatter("%timestamp% [%level%] %logger%: %message%")` | `2026.10.07 07:12:56 [INFO] : a b c F.mq5 %level%` |
| `CDetailedFormatter()` | `2026.10.07 07:12:56.828 [INFO ] mylog: a b c F.mq5 %level% [F.mq5:7:Fn]` |

- Пробелы в тексте схлопнуты (F-20): чистка «лишних пробелов» шаблона идёт по готовой строке.
- `%file%` внутри текста заменён (F-21): подстановки выполняются по очереди по всей строке, а текст вставлен
  раньше. `%level%` уцелел только потому, что его подставили до текста.
- `%logger%` в простом форматтере — пусто (F-22).
- Обработчик журнала без форматтера не печатает код ошибки, имя логгера и место вызова (F-23): `Error("…", 4756)`
  в журнале — без 4756.
- Цвета ANSI журналу MT5 не нужны (F-24).

## Пробел

Сообщение меняется по дороге; строка зависит от порядка внутренних замен.

## Варианты

- Разбор шаблона один раз при `SetPattern` в список кусков (текст / поле); сборка строки — один проход, значения
  полей не пересматриваются.
- Пробелы убирать только вокруг пустого поля шаблона.
- Формат по умолчанию у всех обработчиков один и включает код ошибки, когда он не ноль.

## Предложение

LOG-BL-07 — заодно быстрее: сейчас на запись около десяти `StringReplace` по всей строке.
