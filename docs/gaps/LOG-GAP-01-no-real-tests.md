# LOG-GAP-01: Нет тестов, которые что-то проверяют

**Статус:** закрыт (07.10.2026, LOG-BL-01)  ·  **Дата:** 2026-10-07  ·  **Находки:** F-34  ·  **Задачи:** LOG-BL-01

## Что нужно

Менять библиотеку и знать, что ничего не сломано: 376 вызовов в репозитории `mql` зависят от неё. Каждая
ошибка из разбора должна сначала стать падающим тестом.

## Что есть

- `Tests/LoggerTest.mq5` (456 строк), `Tests/LogTest.mq5` — печатают сообщения вида «should NOT appear»; смотреть
  глазами в журнале. Ни одной проверки, итога нет.
- Подключают `<Logger\Logger.mqh>` — собираются только когда библиотека лежит в `Include\Logger`.
- Оставляют в `MQL5\Files` файлы `test_log.txt`, `test_logs.db`, `detailed_logs.db`, `macro_logs.db`,
  `composite_*.db`.
- `LoggerTest.mq5` в корне — копия из `Tests/` с другим `#include`; ещё одна копия — `Scripts/Logger` в `mql`.
- `.ex5` тестов лежат в репозитории.
- Ни одна из 18 находок, подтверждённых пробой 07.10, этими тестами не ловится.

## Пробел

Нет автоматической проверки. В `mql` есть готовое: `Include/UnitTest.mqh` (`UT_CASE`, `UT_CHECK`, `UT_EQ`) и
`mql-test unit` — запуск из Linux с итогом в JSON.

## Варианты

1. Тесты на `UnitTest.mqh` из `mql` — библиотека начинает зависеть от файла чужого репозитория.
2. Свой маленький каркас проверок внутри `Tests/` (≈50 строк) с тем же форматом итога «N of M passed» —
   `mql-test unit` поймёт, зависимости нет.
3. Тесты держать в `mql` (`Scripts/UnitTests/Logger`), в сабмодуле — только код.

## Предложение

Вариант 2: тесты живут с кодом, запускаются `mql-test unit` через папку-ссылку в `mql`. Решение — в LOG-BL-01.
