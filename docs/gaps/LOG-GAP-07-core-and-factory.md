# LOG-GAP-07: Ядро и фабрика — потерянные записи, владение, имена

**Статус:** открыт  ·  **Дата:** 2026-10-07  ·  **Находки:** F-14, F-25 … F-31  ·  **Задачи:** LOG-BL-06, LOG-BL-09

## Что нужно

Предсказуемое поведение: запись либо записана, либо отвергнута по понятному правилу; объект, созданный через
фабрику, живёт понятный срок; ошибка в имени или повторное создание видны сразу.

## Что есть

**Потеря записей**
- `CLogger::m_global_lock` — один статический флаг на все логгеры. Пока идёт `Log` одного логгера, `Log` любого
  другого сразу возвращается. Проба: обработчик первого логгера пишет во второй — у второго 0 записей (F-14).
  Так же пропадёт запись из форматтера, фильтра или деструктора, вызванных во время записи.
  В README это названо «thread-safety»; в MQL5 программа выполняется в одном потоке.

**Фабрика**
- Недопустимое имя в `GetLogger` молча заменяется на `default`; точка недопустима, иерархии имён нет (F-25).
- Повторное `CreateLogger` с тем же именем — старый логгер, новая конфигурация отброшена, строка в журнал (F-26).
  Так будет при повторном `OnInit` советника без `Shutdown` в `OnDeinit` (смена периода графика: по документации
  глобальные объекты советника при этом сохраняются; не проверено).
- `RemoveLogger` не убирает обработчики, форматтеры и фильтры логгера из реестров; деструктор логгера закрывает
  обработчики, которыми может пользоваться другой логгер (F-27).
- `CreateProfileLogger`: в ветке `default` — `delete` объекта, оставшегося в реестре (F-28).
- `CreateCompositeLogger` ищет обработчик по подстроке пути (F-29).

**Макросы**
- `LOGIF` не собирается (F-30).
- Переменная `logger` внутри макроса; `GetLastError()` читается после `GetLogger()`; `LOGEXECUTION_TIME` на
  `GetTickCount` (F-31).

## Пробел

Запись может пропасть без следа; срок жизни обработчиков не определён; ошибки использования скрываются.

## Варианты

- Блокировка: убрать совсем; от бесконечной рекурсии — счётчик глубины на логгер (вложенная запись проходит,
  глубже N — счётчик потерь и одна строка в журнал).
- Владение: обработчик принадлежит логгеру, к которому добавлен первым; либо счётчик ссылок в фабрике.
- Имена: разрешить точку; недопустимое имя — `NULL` и строка в журнал (макросы уже проверяют `NULL`).
- Повторное создание: вернуть существующий без строки в журнал, если конфигурация та же; иначе — пересоздать.

## Предложение

Блокировка — отдельной задачей LOG-BL-06 (меняет поведение, нужен тест на рекурсию). Остальное — LOG-BL-09, с
коротким проектом по владению.
