# LOG-GAP-03: Запись в файл теряет данные

**Статус:** открыт  ·  **Дата:** 2026-10-07  ·  **Находки:** F-01 … F-06  ·  **Задачи:** LOG-BL-02

## Что нужно

Журнал в файле, который дописывается между запусками, не теряет записи при ротации и открывается в редакторе,
пока программа работает.

## Что есть (проба 07.10)

- **Дозапись стирает файл** (F-01). `FileOpen(имя, FILE_WRITE | FILE_TXT)` без `FILE_READ` обнуляет существующий
  файл. Обработчик создан с `append = true`, записал строку, закрыт; создан снова, записал вторую — в файле одна
  строка. Режим по умолчанию — именно дозапись; `CreateFileLogger` и `file_output` в конфигурации используют его.
- **Ротация теряет записи** (F-02). Предел 300 байт, 60 записей: все вызовы `Handle` вернули `true`, осталось 6
  строк в двух файлах (`…rot.txt` и `…rot_2026.10.07.txt`). Архив называется по дате без времени и перезаписывается.
- Имя архива режется по первой точке пути (F-03).
- Кодировка — UTF-16 с BOM; файл открыт без `FILE_SHARE_READ` (F-04); общая папка терминалов недоступна.
- Файл не открылся — строка в журнал терминала на каждую запись (F-05).

## Пробел

Обработчиком нельзя пользоваться для журнала дольше одного запуска и больше одного файла в день.

## Варианты

- Открытие: `FILE_READ | FILE_WRITE | FILE_SHARE_READ | FILE_TXT | FILE_ANSI` + кодовая страница `CP_UTF8`, затем
  `FileSeek(…, SEEK_END)`; флаг общей папки — параметром.
- Архив: имя с датой и временем либо номером (`ea.1.log`, `ea.2.log`) и пределом числа архивов.
- Сбой открытия: одна строка в журнал, повтор не чаще раза в N секунд, счётчик потерянных записей.

## Предложение

Всё перечисленное — одной задачей LOG-BL-02, сначала тесты на оба случая потери.
